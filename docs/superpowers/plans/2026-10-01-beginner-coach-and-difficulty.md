## 目标与产品结构

让零基础用户逐步学会规则、完成第一盘棋，并能理解和改正自己的错误。

学习路线：**新手学堂 → 吃子练习 → 9 路陪练 → 局后两个重点 → 针对性练习 → 自由对局**。

- **陪练是独立模式**：新增首页入口，使用端侧对手、棋盘提示和可选 API 讲解。
- **难度是独立设置**：启蒙 / 简单 / 中等 / 困难；陪练和自由对局复用同一套对手策略。
- **教练独立分析**：对手按难度选棋，教练使用单独的较强分析预算；异步讲解不阻塞落子。
- **进度是能力记录**：按“独立完成 / 提示后完成 / 尚需练习”记录，支持随时退出和继续。
- 延续现有可爱风格、棋盘与提示组件。主要教学操作直接落在棋盘上，讲解区默认只展示一个重点。

## M1：修正教程，建立可完成的学习路线

1. 修正禁入点执子颜色、两眼棋形、小飞起点与答案不一致等问题；落子、提子和判题复用真实规则引擎。
2. 重排课程：落在交叉点 → 找气与数气 → 提一子 → 连接共享气 → 救棋 → 围地与停着 → 简单两眼；劫与复杂死活在需要时引入。开头说明围棋最终比围地，吃子练习使用单独胜负条件。
3. 每个概念采用“演示 → 有提示操作 → 换局面独立练习”。提示逐级给出：观察方向 → 高亮相关棋块/气 → 展示落点；独立练习不预先显示答案。
4. 先用 5 路局部练习，再进入 9 路完整陪练。吃子练习按教学目标结束；完整对局解释停着、死子和当前应用的计分规则，允许核查自动判定。
5. 分别保存暂停、跳过、完成；末课直接进入第一盘适合新手的陪练。

涉及：`components/TutorialStates.ts`、`components/TutorialModal.tsx`、`components/GameBoard.tsx`、`components/app/AppModals.tsx`、`core/go/rules.ts`。

验收：示例均经规则引擎验证；玩家能在换位置/换颜色、无答案高亮的局面完成提子与救棋；退出后恢复正确进度。

## M2：降低棋力下限，拉开端侧难度

首期保留内部 `Fun/Easy/Medium/Hard` 兼容已有设置；界面对应“启蒙/简单/中等/困难”，旧娱乐模式复用启蒙策略。

| 档位 | 策略方向 | 需要验证的能力差异 |
| --- | --- | --- |
| 启蒙 | 改造现有局部规则 AI，按能力限制连接、一步吃子与救棋；教学关卡使用明确的脚本对手 | 纯新手能发现机会、理解被吃原因，避免一味连续叫吃 |
| 简单 | 借鉴 KaTrain，在受限候选子集中按 policy 选棋；不搜索深变化 | 比启蒙稳定，但仍有可理解的漏看与缓手 |
| 中等 | 扩大候选覆盖范围、提高战术稳定性；若设置搜索预算则真正接入执行 | 相对简单具有可测的优势 |
| 困难 | 完整候选与搜索，在目标设备时延预算内执行 | 相对中等具有可测优势，并保持可接受等待时间 |

- 采样策略与模型推理解耦，支持固定随机种子、配置版本和回放。
- 保留合法性、劫、停着与终局处理；候选限制不能造成非法落子或无故结束。
- 简明棋风与强弱分别控制：优先让新手看懂连接、围地；使用启发式近似时标记为待校准，不宣称等同于 KaTrain 的 ownership 策略。
- 按棋盘尺寸和设备测量；原模型温度、固定 rank 偏置及 AI 积分常量都不作为棋力证据。
- 自动推荐只在局后调整，并允许玩家选回原难度；一局内保持已选择的对手档位。

涉及：`core/go/ai.ts`、`core/inference/selection.ts`、`core/inference/search.ts`、`utils/aiConfig.ts`、`worker/ai.worker.ts`、`hooks/useWebKataGo.ts`。

验收：固定战术局面、多随机种子、相邻档位交换黑白对局；报告胜率、区间、超长局及耗时。先小批筛查，再扩大样本确认顺序。另邀零基础用户验证最低档；机器互战不能替代新手体验。

## M3：增加可信的教练分析层

1. 统一输出 `AnalysisSnapshot`：棋局 ID、局面版本、当前方、规则/贴目、相关棋块及气、捕获事件、候选点、经验证的变化、分析来源和访问数。
2. 区分确定规则事实与模型估计；统一黑白视角、坐标和分数单位。当前候选中的占位零值、policy 排名及未校准原始输出不能包装成真实目损。
3. 基础规则提示直接本地生成；复杂判断等待分析证据。没有充分变化证据时，不宣称“必死/唯一正确”。
4. 给落子与分析请求独立标识，统一调度，避免并发回包串用；悔棋、重开、换局后废弃旧分析和旧讲解。优先保证对局响应，控制教练计算预算。

涉及：`core/inference/engine.ts`、`core/inference/protocol.ts`、`worker/ai.worker.ts`、`hooks/useWebKataGo.ts`；新增教练领域模块，避免继续向教程弹窗堆逻辑。

验收：气数、提子、非法落子、视角和坐标可回归；人工构造慢响应时，旧结果不会作用于新局面；计分口径与实际对局一致。

## M4：新增 API 大模型陪练

1. 首页新增“陪练模式”；界面提供“讲解这一手 / 给点提示 / 为什么不能这样下 / 演示变化 / 回退重试”。默认一两句，结合棋盘圈点、箭头或短变化回放。
2. 默认关键事件或主动提问触发：被吃、危险棋块、非法落子、阶段结束。逐手讲解可选；同一事件合并请求，避免连续打断。
3. API 输入使用证据包、已学概念和最近问题；先讲已学词汇，陌生术语附短解释。LLM 输出限定为说明、证据引用和允许的棋盘标记，不直接决定真实落子或裁判结果。
4. 校验引用坐标、数字及变化合法性；无法通过时使用本地提示或说明证据不足。校验只能降低幻觉风险，不能视为完整正确性证明。
5. 公共服务由后端代理保存服务商密钥，设置调用/长度上限；开发验证使用测试凭据。超时、断网或未配置 API 时，保留端侧对局与规则提示。记录实际调用量和时延后再确定产品额度。
6. 陪练中的提示、悔棋、脚本局记录为学习活动；与自由对局的竞技积分分开。

验收：用固定局面检查正确性、用词和提示层级；实测 API 路径、超时回退、重试、取消与过期响应；LLM 不生成未验证的“必然变化”，用户可随时继续落子。

## M5：把复盘接回练习

- 每局最多自动选两个教学重点：对应具体手数、发生原因、一个可执行改进动作。
- 每个重点提供“回到这里重试”和同概念的已验证练习。首期从规则生成/人工校验题库选题，大模型不独自编题判分。
- 本地能力档案记录独立通过、提示使用、重试与后续复测；不把看完讲解或 LLM 评价当作掌握证据。
- 首页显示“继续学习/继续陪练”和一个建议下一步；根据最近多次表现推荐难度、课程或明确标注的让子练习。

涉及：现有死活题与学习记录模块、首页、局后界面；补齐真实题目难度与概念标签，复用棋谱和分支能力。

验收：从局后问题可以进入可复现的练习；提示后通过不会记为独立掌握；读写失败/版本迁移不会丢失已有进度。

## M6：增强对手自然度与长期分级

- **ScoreLoss**：先实现同一评估器下可靠的逐候选得分，再按预计目损控制选点；验证额外推理成本及稳定性。
- **Simple Style**：具备逐候选 ownership 后，再评估优先稳定双方地盘的棋风，避免与“降低棋力”混为一项。
- **Human SL**：验证额外模型的导出、级位 metadata、输入输出、下载体积、加载内存和推理耗时。Windows 原生 KataGo 与 ONNX 适配作为两条候选路线，按跨平台目标选用。
- 官方人类档位范围 `20k–9d` 不覆盖全部零基础需求；采用 humanPolicy 概率抽样时评估额外搜索带来的增强调偏；9 路单独标定。

准入：目损数据可信、目标设备资源可接受、实测分级有效后再发布这些能力。M1–M5 的基础体验不依赖 M6。

## 交付顺序与总验收

顺序：**M0 修复与技术评审 → M1 → M2 → M3 → M4 → M5 → M6**。M1/M2 是基础改善；M3/M4 形成可体验的陪练首版；M5 完成学习循环。

- 工程：规则回归、异步协议与异常路径测试；按修改范围运行项目测试、类型检查和构建。每次实现前复核当前工作区已有改动。
- 体验：实际检查首页→课程→陪练→结算→复练全过程，并在目标 Windows/移动端检查布局和响应。
- 新手试用：先邀请约 5 位零基础用户，观察能否独立提子/救棋、完成首盘、说清一次失误原因，并在新局面改正；记录卡点与所需帮助，作为迭代依据，不宣称统计普适性。
- 发布判断：最低档可玩、相邻档有证据支持强弱顺序、教程准确、教练不阻塞、断网可继续、复练能回到具体问题。
