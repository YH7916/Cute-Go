# 固定业务流程回归

执行 `npm run test:flows`。无需打开页面或手动操作，也不需要 API 密钥。

命令直接调用真实业务代码，在同一会话中按固定顺序推进并检查中间状态。任一步骤异常、局面错误或旧结果串局都会失败并返回非零退出码。编排与固定目录由 `harness/commands.mjs` 管理；`npm run check` 和现有 CI 也会自动发现这些测试。

| 流程 | 连续执行内容 | 主要防退步点 |
| --- | --- | --- |
| 陪练对弈 | 开局 → 落子 → 启蒙 AI 应手 → 双步悔棋 → 请求中重开 → 再次应手 | AI 回合锁、完整局面恢复、旧定时任务不落入新局 |
| 本地围棋 | 交替落子 → 点已占位置 → 角部提子 → 悔棋 → 再提子 → 两次停着 → 结算 → 重开 | 提子数、轮次、历史与棋盘一致；终局不能继续落子 |
| 五子棋 | 交替落子 → 黑方连五 → 结算 → 重开并落子 | 胜负与终局状态清理 |
| 陪练讲解会话 | 成功 → 401 → 续弈 → 重试 → 请求中重开 → 旧回复到达 → 新局讲解 | 错误保底、局面证据、取消、旧回复不能覆盖正文或清除新请求 loading |
| 讲解 HTTP | 真实 HTTP 成功 → 401 → 非法 JSON → 取消挂起请求 → 恢复 | API 路径、请求编码、响应解析、错误转换、取消后可继续请求 |
| 模型 Worker 生命周期 | 初始化失败 → 重试 → 计算 → 取消并排队新请求 → 释放 → 重初始化 → 计算 | 失败清理、推理串行、请求身份、旧结果失效、资源重用 |
| 真实 ONNX 推理 | 加载项目模型 → 五种尺寸黑白推理 → 在途释放 → 重载同一模型 | 真实策略和 ownership、输入不变、释放后拒绝推理、重载结果一致 |

## 实现与边界

- 测试位于 `tests/flows/`，复用 `tests/helpers/loadTestModule.mjs`、已有 hook 宿主与生产状态/规则代码；没有另一份围棋算法。
- 对弈流程使用真实启蒙算法，控制时间和随机输入保证可重复；音效、浏览器全局与 React 渲染宿主由测试替代。
- 陪练会话控制 HTTP 响应以覆盖迟到回包；HTTP 流程另外启动绑定 `127.0.0.1` 随机端口的临时服务，实际经过生产 `fetch` 和解析路径，结束后关闭。
- Worker 流程使用实际消息入口、调度与生命周期代码，仅替代 ONNX 初始化、推理和释放边界。这不证明真实模型文件、WASM、GPU 或手机适配正常。
- `onnx-real-flow.test.mjs` 另走真实生产 `OnnxEngine`、`onnxruntime-web` 与项目模型/WASM，自动执行 5/9/10/13/19 路黑白推理和释放重载；不替代 `InferenceSession` 或 `session.run`，不新增依赖。此项覆盖 Node 单线程 WASM，缺失或损坏模型会使测试失败。
- 不读取玩家保存的配置、不访问付费供应商、不修改用户对局。界面、触摸、跨域策略及 Android/TapTap 仍需对应环境验收；浏览器生产 Worker 的独立真实推理结果见 [本机 ONNX 验收](verification/2026-10-02-real-onnx.md)。

调试单条流程可用 `npm test -- tests/flows/game-flow.test.mjs`；交付前运行 `npm run check` 和 `git diff --check`。不要用只打印错误却仍返回成功的临时脚本替代这些断言。
