# 经典棋子点光兼容修复

## 现象与依据

- Fold6（SM-F9560，Android 16）在 TapTap 2.96.13 的 X5 48919 容器内，经典黑子内部变成浅灰白色，顶部黑子图标同步异常。
- 真机已复现：打开原生“更多操作”二级菜单时，黑芯和局部高光恢复；关闭后立即复发。用户另有 OPPO 手机未出现异常，未取得该设备的内核/GPU 对照信息。
- 优先怀疑点光滤镜在不同设备绘制路径中的兼容问题；未证明具体 GPU、精度溢出或缓存机制，不以品牌名单判定。
- 原始截图、内核日志和排查过程在 `output/stone-adb/`。

## 修改

`BoardDefinitions.tsx` 与 `StoneSkinPreview.tsx` 的黑白高光光源由 `fePointLight(-500,-500,300)` 改为 `feDistantLight(azimuth=225,elevation=20)`。棋盘和 ScoreBoard 继续复用 `StoneFilters`。

固定左上方向避免依赖光源到屏幕像素的大坐标向量，保留原有模糊、alpha 融合、凸面高光、底色与阴影参数。原点光的高光曾随棋子位置略有变化；现在方向和强度一致，因此不宣称像素完全相同。新拟物皮肤、棋子半径、连接块、独立棋子策略均未改动。

## 验证

- 新增三处渲染入口的光源回归：棋盘、顶部图标、商店预览。旧点光实现先失败，修改后通过；此测试约束修复路径，不模拟 X5 GPU。
- 24 组完整 DOM/SVG 快照：将新方向光节点逆替换成原点光后，全部匹配原有 SHA256；确认其余节点与参数未变，再更新快照。
- 相关测试：70/70 通过。
- `npm run check`：contracts → lint → typecheck → test → build 全通过，1348/1348 测试，前端 `dist/` 和后台 `dist-server/` 已构建。
- `git diff --check` 通过。
- Chromium 实际检查：9/19 路连体与独立棋子的黑芯、高光与表情；外观商店选择经典、顶部图标更新、实际落子及窄屏显示。截图在 `output/stone-adb/classic-after-desktop.png`、`shop-after.png`、`game-after.png`。

## 尚未覆盖

新构建尚未进入失败设备的 TapTap/X5 容器，不能以普通 Chromium 验证代替原生验收。TapTap H5 自测需要开发测试包；已准备本地 ZIP，未上传、提审或发布。

真机验收必须在菜单关闭时检查，并覆盖冷启动、黑白落子、连续落子、连块/独立模式、缩放、二级菜单开关，以及顶部图标和商店预览。还未复验 OPPO、外屏/折叠状态。
