# 简单档与启蒙衔接验收

日期：2026-10-02。问题：启蒙为局部启发式，旧简单直接从模型全盘候选采样，玩家感到两档之间难度陡增。

## 本轮行为

- 启蒙的候选、落点分布和随机调用保持原样。
- 简单复用 `getBeginnerAIMove`：先按原有提子、叫吃、连接和气数启发式筛出前三候选，再用单次模型推理的 prior 调整抽样权重。每点权重限定为 1–3，模型不能引入池外推荐点；模型温度改为 0，不再使用旧全盘高温加排名偏置的采样策略。
- 合法性与劫仍复用 `attemptMove`。Worker 的模型优先停着、禁止过早停着及合法落子兜底保留；局部候选被过滤完时返回 null，允许停着时可能比旧简单更早结束填眼阶段。
- 中等、困难、模型加载和异步请求所有权不变。中等配置中的 simulations 仍未用于多次搜索，本轮不扩大范围修正。

## 回归与完整检查

先保存旧实现，再增加回归；旧实现的 17 项选点测试有 8 项失败，6 项 Worker 测试有 1 项失败。修复后新增 23 项全部通过；Worker 测试复用实际温度配置，同时保留独立搜索次数断言。

覆盖启蒙固定随机结果及调用次数、简单局部候选与有界抽样、异常 prior、空/满盘、黑白视角、自杀/真眼/劫、输入不变、停着和兜底、真实 Worker 消息入口、中等单次推理与困难 10/25 次预算。

最终 `npm run check`：contracts、lint、typecheck、**598/598 测试**、生产 build 全部通过；`git diff --check` 通过。构建保留现有 Browserslist 数据过期和 ONNX 依赖 eval 提示，无构建失败。

通过独立浏览器页面手动触发，使用本地 `kata_dynamic.onnx`，未读取玩家 API 设置或调用云服务。临时验收脚本复用 `bundleTestSource`；修改前 bundle 与最新 bundle 对比，不在网页中另写选点算法。

## 限制

这证明简单已切换为与启蒙相同的局部策略，并保留有限模型偏好；不证明固定段级、Elo、对人胜率或整个难度梯度已校准。某些局部战斗会因启发式优先提子而比旧简单更强，不能承诺每个局面都降强。全局模型候选排名不是棋力或失分指标。

尚未完成新手实玩、长局对弈统计、Android 真机及不同硬件性能验收。浏览器耗时仅代表本次桌面环境，35 手广覆盖局面也不代表所有复杂中盘的最坏耗时。
