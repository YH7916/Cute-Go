# 陪练简洁教学验收

日期：2026-10-02。范围：教学触发、内容优先级、本地兜底与云端提示；不改棋盘落子规则、对手难度和模型加载。

## 改动

- 普通落子、单纯提子和解围不主动播报；只在本手新增打吃或自陷一气时提醒，已是一气的延伸不重复触发。
- 修正“同手提子＋打吃”的优先级：先告诉玩家自己的棋面临什么危险，不让提子播报盖住解围需求。
- 本地正文压为一两句，删除手数、提子数量、轮到谁等复述。普通孤立落子被手动询问时不硬套数气/斜连知识；真实存在斜连、贴边、连接或紧气时才解释对应要点。空盘/尚无己方棋不要求找己方弱棋；对手回合不要求玩家立即落子。
- 提示优先展示规则已验证的解围/提子点，其文字和标记来自同一候选；没有此类候选才展示引擎建议。
- 自动请求的 `proactive` 标识贯穿 hook 预览、必要性复核、Agent 和云请求。服务可用专用标记表示无需补充；手动请求或格式不规范的标记退回本地回答，不把标记展示给玩家。
- 云端默认要求 1–2 句、30–60 字、最多 80 字，优先“问题为什么重要、下一步看什么”；要求前置并配短示例，默认用白话。规则追问允许完整说明必要条件。保留完整回复，不按字符硬切，也不追加自动付费重试。

## 验证

规则、触发和运行边界先补回归复现，再改实现：包含黑白双方同时提子与打吃、普通结果静默、自动/手动请求区分、静默标记泄漏、空盘时机、可执行解围优先、无依据斜连教学。旧局面、重置、撤销、取消、密钥处理和 Worker 生命周期继续跑既有回归。

最终 `npm run check`：contracts → lint → typecheck → **611/611 测试** → build 全部通过；`git diff --check` 通过。保留依赖的既有 Browserslist 数据过期及 ONNX eval 构建提示。

本机浏览器用真实生产教学 Worker、真实规则构造局面：黑白各 7 例，共 **14/14** 通过。检查普通场景静默、新危险 39 字提醒、手动普通落子 22 字回复、解围提示 44 字及合法标记、输入局面不变。此组没有 API 配置，不读取玩家存储或调用云端。

另在独立应用页通过正常 UI 使用玩家已保存的服务实测同一开局问题。首次回答 121 字，暴露提示虽声明简洁但实际偏长；前置要求、加入示例后缩为 46 字。该回答仍出现未解释术语，因此补充默认白话约束；最终实测 39 字：“可以从角部附近开始，角上借两条边更容易围空，也别贴边太近，留出向外发展的空间。”本轮共三次手动请求，未读取或输出密钥，也未修改供应商设置。

本机原始证据在 `output/coach-teaching/`：`before.log`、`marker-before.log`、`quiet-before.log`、`opening-before.log`、`final-check.log`、`browser-worker.json`、`cloud-first-sample.json`、`cloud-final-sample.json`、`cloud-final-sample.png`。这些为本地临时验收产物。
