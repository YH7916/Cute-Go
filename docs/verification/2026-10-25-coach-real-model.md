# 真实模型讲解、圈点与连续追问实测

## 修正前基线

2026-10-25，本机 H5 → 真实 ONNX → 独立 Pi 后台 → DeepSeek `deepseek-flash` → 真实 renderer。使用用户在测试页面填写的 key；采集内容不含凭据或请求头。已关闭本轮隔离浏览器与自建前后端进程。

固定局面由 `attemptMove → recordMove → buildCoachEvidence` 建立，SGF 回导一致；为保留陪练模式，通过现有 `AppView.gameState.writePosition` 装载完整状态。这是固定局面集成测试，不是普通导入界面的验收：产品的导入操作会关闭陪练模式。提子前后在同一会话追加两手，保持历史根身份；没有重置后伪称连续追问。

完整捕获 14 次模型响应，包含一次相同数气问题的重复，以及一次提子前的错误前提提问；另有两次抓包准备请求未取得完整原文，不纳入评分。浏览器抓包把一次请求转发到真实后台，再原样交回响应，没有预设模型答案。每个已捕获响应的 usage 均为一次模型调用。

### 具体问题

1. **圈号未参与选材。** B1实际输出①=E4白棋、②=D5黑棋、③=D4黑棋；B3追问②，历史对照正确，但本轮只选了`group.G7`，漏掉D5黑组。模型错误回答“②是白棋，G7这颗白子有4口气”。本次拒绝来自它直接写了圈号，并非系统识别了棋理错误。
2. **坐标许可误拒。** 六条原文包含真实棋盘上的气点或提子落点，却未出现在所引条目的字面坐标列表中，整段回退。A1c正确报出4口气并列举气点，另因总计五个位置超过三点硬上限被拒。
3. **数字许可误拒。** C2正确说“不用数两次”，但否定中的“两次”不在引用项的数字列表内，回退为无关开局建议。

## 按用户要求直接展示云文案

用户明确要求优先采用云文案后，移除了数字同值、引用项坐标列表和确定性词的字符串裁决；保留JSON、有效引用ID、50字一句、棋盘范围与标记绑定。三个点改为生成建议，正文中更多合法点完整绘制，复盘与历史也保留后续编号。旧parts选择协议仍保留原规则。

同一批14条真实回包在新版renderer中回放，接纳由 **6/14提升至13/14**；唯一仍拒绝的B3含模型自行写入的未绑定圈号。这个结果只证明不再误拒那7条既有正确文案，不证明新prompt已经消除了模型指代错误。[新版回放数据](../../output/playwright/coach-cloud-prose-replay.json)

新prompt要求数气先报数量，未问气点时不逐点列举，并让模型直接使用本轮规则事实组织措辞。端侧新增`questionReferences`，从实际已显示标记解析追问目标，参与本轮棋块/概念选材和ONNX关注点；被提走的旧位置不改指其他棋块。后续程序回归与浏览器回放单独记录，不与上述真实模型基线合并统计。
