# 第二轮代码治理：保留玩家体验，减少维护隐患

本文记录第二轮完成时的结果；后续 TapTap 类型债、SDK 边界和异步会话问题已处理，当前结果见 [第三轮 TapTap 治理](taptap-governance-2026-10-01.md)。下方 217 项测试与 35 处 any 为第二轮快照。

## 已落地

| 隐患 | 改动 | 行为证据 |
| --- | --- | --- |
| GameBoard 同时承担派生、手势、计时器和 SVG 绘制 | 主组件从 1212 物理行降至 213 行；按职责拆到 `components/board`，新模块均低于 400 有效行 | 拆分前固定 36 组完整 DOM/SVG 哈希，拆分后逐字节一致；另有 6 组派生与 8 组交互 hook 回归 |
| 同步/Worker 各有一套五子棋搜索，修复容易漏一端 | `core/gomoku/search.ts` 为唯一搜索内核，`profiles.ts` 显式保存两端策略；Worker 只调用入口 | 先固定旧实现选择结果；真实 Worker、双方战术、难度/预算/候选顺序、正常/超时/异常棋盘还原回归；独立 72 次旧/新同步差分落点一致 |

| 五子棋延迟终局可能污染重开后的新棋盘 | 0ms 终局回调校验提交局面的身份 | 原局面仍终局；重置后的旧回调失效 |
| 清债后旧豁免仍可能被继续使用 | 移除 GameBoard、Worker、useWebKataGo 的超长文件预算；清理死活题/音频的类型逃逸并 prune 存量额度 | 默认 400 有效行重新覆盖上述文件；当前类型债仅 TapTap 桥接层 35 处 any |

保留既有用户的五子棋战术修复和设置文案修改。本轮整合了工作区并行完成的 AI 请求/引擎生命周期、迟到分析结果与缓存修复，最终检查涵盖这些当前源码；这些不是本轮单独重写的模块。

## 行为边界

- 同步 Easy/Medium/Hard 深度仍为 2/3/4；Worker 仍为 2/4/8，100/800/3000ms 预算，原排序、宽度、偏置均保留。
- Worker 仍只在根候选之间检查超时，3000ms 不是严格递归中断上限。
- 满盘 Worker 回包从旧 `undefined` 明确为 `null`；同步入口保留历史中心 fallback。
- UI 保留 DOM、样式、绘制顺序；视觉气线仍是一颗棋子到相邻气点的一条边，不替换成棋群去重气数。
- 旧字段 setter/ref 暂时兼容，设置、死活题、复盘仍需逐步迁移；不宣称全部状态都已成为单一状态机。

## 后续优先级

1. **复盘分析的一致性**：`AppView` 使用动作前棋盘，却发送包含该动作的历史并反转行棋方。先补显示棋盘/推理历史对照回归，再单独修正；本轮未改变复盘分析语义。
2. **TapTap 原生验收**：第三轮已收口原生声明、payload 校验并清理 35 处 any；仍需设备/在线重复消息回归，不能只靠 fake SDK 验收。
3. **编排与剩余状态迁移**：缩小 AppController、useOnlineMatch；将设置/死活题/复盘迁移至完整局面动作，补终局幂等及异步在线消息与重置竞争的测试。
4. **发布链路**：`version:sync` 引用缺失的 `update-version.js`，Android 发布需独立修复、真机验收。

后续修改遵循根 `AGENTS.md` 与 [当前架构](architecture.md)。每项先固定行为或复现故障，再迁移实现；不得增加行数预算、类型债额度或跳过失败测试。
